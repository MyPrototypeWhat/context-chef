Cache stability: keep the prompt prefix byte-stable across compiles.

- **Static memory tool definitions**: `modify_memory` no longer embeds an enum of live keys and is always emitted (previously it appeared only when keys existed and its schema changed on every key mutation — invalidating the entire provider prompt cache, since tools are the topmost prefix segment). Visible keys are still surfaced via the injected memory block's "Existing memory keys" guidance (the SELECTED keys — a `selector` is the caller's visibility policy, and keys it hides stay modifiable through dispatch-time validation). `getToolDefinitions()` returns a fresh array per call (append/reorder freely); the definition objects inside are frozen and reference-stable, keeping `payload.tools` deep-equal across compiles.
- **`withGuardrails({ placement: 'last_user' })`**: delivers the enforce-XML instruction through the last-user-message tail injection instead of a system message. On Anthropic, all system-role messages are hoisted into the top-level `system` prefix — the new placement keeps guardrail changes from invalidating cache breakpoints. `prefill` behavior unchanged.
- **`auditAnthropicCachePlacement(payload)`** + **`ChefConfig.cacheAudit`**: deterministic, Anthropic-only audit that flags volatile content (memory data, dynamic state, implicit context, guardrail instructions) sitting inside the cached prefix (at or before the last `cache_control` breakpoint), with a per-issue suggested fix. A breakpoint that sits ON the volatile tail segment gets its own diagnosis (move the breakpoint) instead of circular placement advice. Issues carry a position-independent `dedupeKey`; `cacheAudit: true` warns each issue KIND once per chef instance, even as history growth shifts message indices.
- **Tail injection placement (fix)**: the assembler now places tail-injected content (dynamic state, guardrail `'last_user'`, memory `'before_history_tail'`, implicit context) at the true conversational tail. Mid-agent-loop compiles (history ending in tool results) append a NEW user message after the tool results instead of rewriting the user turn that started the tool sequence — prior history stays byte-identical, so provider prefix caches survive. With no user/tool message at all, the injected user message now lands BEFORE a trailing assistant prefill (the old shape ended `[assistant, user]`, which Anthropic rejects and which silently disabled the prefill).
- **`createTokenizerAdapter(encode)`**: zero-dependency glue that turns any `(text) => tokens` encoder (gpt-tokenizer, js-tiktoken, …) into a correct `JanitorConfig.tokenizer` — counting content, thinking, redacted-thinking data, AND tool-call names/arguments (the field most hand-rolled adapters miss). Approximate cross-provider counts are safe under the default `triggerRatio: 0.7` headroom.
- **Skill loader validation**: `SkillLoadResult` gains an optional `warnings` array (optional in the TYPE for source compatibility with existing result literals; the loaders return `Required<SkillLoadResult>` and always populate it). `loadSkillsDir(s)` report mechanical issues (missing/thin description, oversized instructions, malformed `allowedTools`, dangling relative resource links) without ever blocking a load. `loadSkillsDirs` only reports warnings for skills that survive precedence resolution — a shadowed skill's findings are dropped with it.
