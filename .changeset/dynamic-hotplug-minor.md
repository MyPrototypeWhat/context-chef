Dynamic hot-plug: cache-safe channels for mid-session capability changes.

- **`Message._positional`**: a `role: 'system'` message marked positional stays AT ITS POSITION in the message stream instead of being hoisted into the provider's top-level system parameter. Anthropic renders it as a mid-conversation system message (native on Fable 5 / Mythos 5 / Opus 4.8 / Opus 5 — cached prefix stays intact, operator precedence; NOT supported on Sonnet 5), falling back to hoisting with a one-time warning when it precedes every user/tool message (`AnthropicAdapterOptions.logger` is new). OpenAI Chat Completions is inline already; the Responses adapter now emits a positional system message as an inline `message` item instead of folding it into `instructions`; Gemini degrades it to a `user` content entry verbatim.
- **`ChefConfig.skillPlacement: 'after_system' | 'tail'`** (default `'after_system'`, unchanged behavior): under `'tail'`, the active skill's instructions leave the cacheable prefix entirely and lead the tail stitch wrapped in `<skill_instructions skill="...">`. Activating or switching a skill then never invalidates the cached prefix — the trade-off is that the instruction tokens are re-sent in the uncacheable tail on every request. Pick `'tail'` for agents that switch modes frequently, `'after_system'` for a long-lived mode.
- **Announcements** — `chef.announce(id, content, { channel })` / `chef.retractAnnouncement(id)` / `chef.getAnnouncements()`: standing statements of current capability state ("Tools newly available: X, Y"), rendered into every compile until retracted. Because ContextChef's injections never persist into your history, retraction removes them completely. Channels: `'user_tail'` joins the tail stitch (after implicit context, before the anchor); `'system'` renders one combined `_positional` system message after the conversational tail; `'auto'` (default) routes by target — system on Anthropic, user_tail elsewhere (Anthropic + Sonnet 5 callers should pass `'user_tail'` explicitly). Announcements ride `ChefSnapshot` (old snapshots restore to an empty set) and survive `clearHistory()`. No automatic tool-delta detection — diff your tool list in userland and call `announce()` (mechanism, not policy; recipe in the JSDoc).
- **Cache audit** learns the two new tail channels: `<skill_instructions` and `<announcements>` caught inside the cached prefix are flagged with move-the-breakpoint guidance.
- `ToolDefinition.deferLoading` docs now cover the `tool_addition` beta precondition and cache-key stripping semantics. `tool_addition`/`tool_removal` content-block pass-through is out of scope for this release (ContextChef's IR is text-content based).
- **Fix (present since 4.0)**: the compile re-entrancy flag was never reset after the first `compile()`, so every subsequent call took the re-entrancy bypass and the Snapshot + Serialize concurrency queue was permanently disabled. The flag now resets when the outermost compile finishes (nested hook-driven compiles still bypass correctly).
- Round-trip note: `fromAnthropic` / `fromOpenAIResponses` now SKIP mid-stream system entries (positional channel output) instead of parsing them into history / folding them into the system layer — re-ingesting volatile announcement text as durable history would bake it into the cached prefix and defeat `retractAnnouncement()`.
